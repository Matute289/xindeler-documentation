# Technologies

Xindeler's technical stack. All dependencies are open source.

## Language

### Rust (nightly)

The game and server are written 100% in Rust. The **nightly** channel is used because the project depends on compiler features that haven't stabilized yet (mainly `portable_simd` and some procedural macros).

The exact channel required is pinned in `rust-toolchain.toml` at the repo root.

## Server

### specs — ECS

[specs](https://github.com/amethyst/specs) is the Entity Component System framework. It automatically parallelizes systems using `rayon` when their component sets don't overlap.

### Quinn — QUIC transport

[Quinn](https://github.com/quinn-rs/quinn) implements the QUIC protocol (RFC 9000) in Rust. The game protocol runs over QUIC instead of TCP because:
- Stream multiplexing without head-of-line blocking
- Faster reconnection after packet loss
- Better behavior on mobile networks and with NAT

### MessagePack — Persistence

The world state (`rtsim/data.dat`) is serialized with [MessagePack](https://msgpack.org/) via the `rmp-serde` crate. It's a compact, fast binary format compatible with `serde`. There is no relational database.

### RON — Assets and configuration

[RON (Rusty Object Notation)](https://github.com/ron-rs/ron) is the text format used to define items, abilities, creatures, recipes, and server configuration. It's similar to JSON but with native support for Rust types (enums with variants, structs with field names).

Example of an item in RON:
```ron
ItemDef(
    name: "Espada de Hierro",
    kind: Sword(
        equip_slot: Mainhand,
        power: 12.0,
        speed: 1.2,
    ),
    quality: Common,
)
```

## Client (Voxygen)

### wgpu — Rendering

[wgpu](https://wgpu.rs/) is a GPU abstraction that implements the WebGPU standard. It supports multiple backends:

| Operating system | Backend |
|-------------------|---------|
| Linux | Vulkan |
| macOS | Metal |
| Windows | DirectX 12 / Vulkan |
| Fallback | OpenGL (via `WGPU_BACKEND=gl`) |

The rendering pipeline renders voxel chunks with dynamic LOD (level of detail).

### egui — UI

[egui](https://github.com/emilk/egui) handles the client's user interface: HUD, inventory, menus, dialog windows. It's an immediate mode UI — there is no persistent widget tree.

### rodio / CPAL — Audio

The audio system uses [rodio](https://github.com/RustAudio/rodio) on top of [CPAL](https://github.com/RustAudio/cpal) for playing ambient music, sound effects, and in the future the voices generated by AURORA.

## Web (separate process)

### FastAPI (Python)

The web process is written in Python with [FastAPI](https://fastapi.tiangolo.com/). It exposes three REST endpoints for the waitlist, the contributors form, and server status. It has no access to the game state — it queries the game server via an internal status endpoint.
